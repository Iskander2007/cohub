# 📕 COHUB · Playbook (что делать при аварии)

Короткие инструкции на 4 типа аварий. Общий справочник по проекту — `RUNBOOK.md`.
Ход мысли для «а что если…» — `SCENARIOS.md`.

Алерты приходят в **Telegram** (настроено в `monitoring/alertmanager/alertmanager.yml`).

---

## 🔗 Быстрые ссылки

| Что | Где |
|---|---|
| Проверка сайта | `GET /health/` (ждём `200` + `"status":"ok"`) |
| Сводка + что горит | `GET /api/metrics/summary/` |
| Grafana (графики) | http://localhost:3000 |
| Prometheus (алерты) | http://localhost:9090 |
| Alertmanager | http://localhost:9093 |
| Логи | `logs/errors.json` · `logs/requests.json` · `logs/payments.json` |

> Логи в файлах — локально и в консоли сервера. На проде (Render) логи — в панели: сервис → **Logs**. Для команд с логами нужен `jq`.

---

## 🧭 Общий порядок при любой аварии

1. **Подтверди:** `curl -s https://<АДРЕС_САЙТА>/health/` и `/api/metrics/summary/`.
2. **Останови кровь:** перезапусти или откати релиз (памятка внизу).
3. **Найди причину:** по логам (`logs/*.json`).
4. **Проверь, что помогло:** health снова `ok`, алерт погас.

Самый быстрый фикс почти всегда — **откат релиза или перезапуск**.

## 🟥 Сайт не отвечает (Server Down)

**Алерт:** `CohubServerDown` — Prometheus не может опросить сайт больше 1 минуты.

**Что делать:**
1. Открой `GET /health/`.
   - Отвечает `200` → сайт живой, проблема в сборе метрик (см. пункт 4).
   - Не отвечает / ошибка → сайт действительно лёг, идём дальше.
2. Смотри, что именно упало — тело `/health/` покажет:
   - `"database":"error"` → недоступна база (проверь `DATABASE_URL`, статус БД).
   - `"cache":"error"` → недоступен кеш.
3. Проверь процесс и последние ошибки:
   ```bash
   # Render → Logs   |   на своём сервере:
   ps aux | grep gunicorn
   tail -n 50 logs/errors.json | jq .
   ```
   Резкий рост памяти перед падением = вероятный OOM (не хватило RAM).
4. Если `/health/` = `200`, а Prometheus всё равно DOWN — сломан скрейп, а не сайт: хост должен быть в `DJANGO_ALLOWED_HOSTS` (для Prometheus — `host.docker.internal`).

**Починить:** перезапусти сайт; если упал сразу после релиза — откати.
**Проверить:** `/health/` = `200`, в Prometheus таргет снова UP, алерт погас.

## 🟧 Много ошибок (High Error Rate)

**Алерт:** `CohubHighErrorRate` — больше 5% запросов с ошибкой уже 5 минут.
Больше 50% → `CohubErrorStorm` (это уже «Server Down», см. выше).

**Что делать:**
1. Оцени масштаб: `GET /api/metrics/summary/` → блок `alerts`.
2. Найди, где ошибки — топ падающих путей:
   ```bash
   tail -n 500 logs/errors.json | jq -r '.path' | sort | uniq -c | sort -rn | head
   ```
3. Один путь → баг в этой странице/её зависимости. Много разных путей → общая причина (база, кеш, PayPal).
4. Совпало с релизом? `git log --oneline -10` — если да, **откати**.

**Проверить:** error rate < 5%, новых ошибок по проблемному пути в `logs/errors.json` нет.

## 🟨 Всё медленно, но без ошибок (High Latency)

**Алерт:** `CohubHighLatency` — p95 больше 5 секунд. Ранний сигнал — `CohubElevatedLatency` (p95 > 2с).

**Что делать:**
1. Проверь ресурсы в Grafana (панель Saturation):
   - CPU > 80% или RAM > 85% → упёрлись в ресурсы, нужен скейл.
   - Ресурсы в норме, а всё равно медленно → узкое место в базе или внешнем вызове.
2. Найди медленные страницы:
   ```bash
   tail -n 500 logs/requests.json | jq -r '[.latency_ms, .path] | @tsv' | sort -rn | head
   ```
3. Помни про наш проект: gunicorn в проде на **1 воркере** → запросы идут по очереди; частая причина — медленные запросы к базе (нет индекса, N+1).

**Норма:** p95 < 2 секунд (базовая линия — около 640 мс при 100 пользователях).

## 💳 Платежи не проходят (Payment Failures)

**Алерт:** `CohubPaymentFailureRateHigh` — больше 10% неуспешных платежей за 30 минут.

**Что делать:**
1. Смотри платёжные логи:
   ```bash
   tail -n 100 logs/payments.json | jq 'select(.status=="failed" or .event_type=="payment_error")'
   ```
2. Проверь провайдера: доступность PayPal, правильность ключей, режим (sandbox / live).

**Важно:** неоплаченные заказы остаются `pending` — деньги не теряются, вебхук/повтор доберёт позже. Падение платёжки не роняет остальной сайт.

## 🔁 Откат и перезапуск (памятка)

- **Перезапустить:** Render → сервис → Manual Deploy → **Restart**.
- **Откатить:** Render → Deploys → выбрать прошлую рабочую версию → **Rollback**.
- **Откат через git** (пуш в `main` сам запускает деплой):
  ```bash
  git revert <плохой_коммит> && git push origin main
  ```
